feat(webui): rebuild the management page, verified by real rendering

Fixed
- ancli status --json fell through to the branch that fetches the cloud registry
  first, so a retry diagnostic landed on stdout ahead of the payload and the
  WebUI's JSON.parse failed (the status strip kept stale values). status is now
  dispatched before the registry fetch and its dead duplicate branch is gone.
- The page scrolled sideways: long unbreakable content (configured-key lists,
  JSON in the output panel) widened the layout past the viewport. Grid children
  can shrink now (min-width: 0) and long values wrap instead of being clipped.
- Action buttons stay disabled while a job runs, so a double tap cannot start two
  installs, and a stale re-render cannot re-trigger the running action.

Changed
- Layout and visual language rebuilt on a neutral surface palette with one bronze
  accent, hairline borders and a single soft shadow. The liquid-glass blur on
  every card is gone: only the sticky bar and the dialog sheet blur, and the blur
  is dropped while the soft keyboard is open.
- Status strip answers rootfs / proot / installed / updates available; the module
  version lives in the header where it already was.
- Tool rows: status monogram, name plus state chips, description, then a muted
  detail line for official version, source and configured keys. Updateable tools
  get an accent rail and an accent action button.
- Output panel: capped at the last 500 lines with a counter, auto-scroll toggle,
  copy-all and clear. status/list --json payloads are no longer dumped there
  (quiet path, failures still shown), the bridge connects with one log line.
- Config dialog is a bottom sheet now: Esc / backdrop / close, body scroll lock,
  provider chips scroll horizontally, hints no longer duplicate placeholders, and
  the proxy fields fold into an "advanced" section.
- Accessibility: focus-visible rings, aria-live regions, reduced-motion support,
  safe-area insets.

Verification
- New local harness .webui-preview/ stubs window.ksu with payloads captured from
  the device and renders the page in headless Chrome, which is how the sideways
  overflow and the duplicated hint text were caught (light, dark, dialog and
  console screenshots). Deployed to the module webroot (0644, no BOM, LF) and the
  page loads against the live bridge on the device.
- Tests: 133 passing; the inline script passes node --check.
