fix(boot): real DNS inheritance, verified over three reboots

Boot path (service.sh):
- DNS no longer leads with 8.8.8.8 (blocked or poisoned on many networks) and no
  longer relies on getprop net.dns1/2, which is empty on modern Android. The boot
  script reads DnsAddresses from /system/bin/dumpsys connectivity (absolute paths:
  a service script's PATH is minimal), writes China-friendly fallbacks immediately
  because late_start usually runs before Wi-Fi/data connects, and then watches in a
  background subshell for up to five minutes, rewriting the file with the real
  resolvers once they appear. Measured on device: fallbacks right after boot, and
  43.239.172.1/43.239.172.2/223.5.5.5 about 75s later.
- Stale host shims are removed from the module's own system/bin too (the leftover
  bash entry exec'd the ksu shim this release stopped populating). Verified gone
  after a reboot; the ksu path was already clean.
- Config-ownership repair extended to .agents/.dsh/.grok/.mimocode; all show
  shell:shell 0700 after a reboot, and the wrappers (dsh/claude/ancli) plus
  installed.json, the update cache and the skills links all survived.

Container DNS:
- The core cannot run Android's getprop/dumpsys from inside the glibc guest
  (verified on device: they do not execute there), so ancli_env.sh probes the
  resolvers on the host and caches them in .dns_cache (hourly);
  _get_android_dns() reads the cache first, prefers IPv4, then falls back to
  public resolvers. AnCLI repair now writes the network's real resolvers instead
  of a 223.5.5.5-only list.

Findings:
- dsh tui does not exist: the device reports that profile tui does not exist,
  upstream ships no terminal app bundle in PROFILE_TEMPLATES and npm publishes no
  TUI bundle for the scope. pnpm was deliberately not installed; README now states
  that the Web UI and dsh headless are the real interfaces.
- KernelSU's su -c resolves only the first command through /data/adb/ksu/bin, so
  chained tool checks are misleading; documented in AGENTS.md.

Tests: 133 (DNS cache/props/dumpsys discovery, resolv.conf ordering, skills).
